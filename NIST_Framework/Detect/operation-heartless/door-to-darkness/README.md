# 🔑 Project: Door to Darkness (SOAR Active Defense Module)

## Overview
**Door to Darkness** is the automated remediation and active defense engine within the **Operation Heartless** SOC framework. Operating as a lightweight SOAR (Security Orchestration, Automation, and Response) listener, it ingests alert payloads fired by Grafana Loki Ruler and dynamically locks down host/network access via system firewall rules (`iptables`).

---

## 🏗️ Architecture & Remediation Flow

+------------------------+      +-------------------+      +-------------------------+
| Zeek NDR / Auth Logs   | ---> | Grafana Loki      | ---> | Loki Ruler              |
| (Network & Host Data)  |      | Log Aggregation   |      | (Evaluates LogQL Rules) |
+------------------------+      +-------------------+      +------------+------------+
|
| Webhook Alert
v
+------------------------+      +-------------------+      +-------------------------+
| Host Firewall          | <--- | lock_door.py      | <--- | Door to Darkness        |
| (Appends iptables DROP)|      | (Python Webhook)  |      | Webhook Listener (:5001)|
+------------------------+      +---------+---------+      +-------------------------+
|
v Audit Log
+-------------------+
| block_events.log  |
+-------------------+


1. **Detection:** Loki Ruler continuously evaluates LogQL rules (such as `GummiShipPotentialPortScan` or `SSHBruteForceAttempt`).
2. **Alert Dispatch:** Upon triggering, Loki fires an HTTP POST payload containing the offending IP (`id_orig_h` or `instance`) to the `Door to Darkness` webhook.
3. **Automated Enforcement:** `lock_door.py` extracts the source IP, verifies whether an `iptables DROP` entry exists, and appends a new rule if unblocked.
4. **Audit Trail:** Every block event is recorded with timestamped metadata into `logs/block_events.log`.

## 🚀 Deployment & Operations

### 1. Launch the Listener
Start the Flask SOAR webhook server on port `5001`:

```bash
python3 ~/Portfolios/operation-heartless/door-to-darkness/scripts/lock_door.py
2. Test Alert Ingestion
Simulate an incoming alert payload from Grafana Loki:

Bash
curl -X POST [http://127.0.0.1:5001/webhook](http://127.0.0.1:5001/webhook) \
  -H "Content-Type: application/json" \
  -d '{
    "alerts": [
      {
        "labels": {
          "alertname": "GummiShipPotentialPortScan",
          "id_orig_h": "192.168.1.200",
          "severity": "warning"
        }
      }
    ]
  }'
3. Verify Active Firewall Rules
Confirm that the target IP has been blocked in iptables:

Bash
sudo iptables -L INPUT -v -n | grep "192.168.1.200"
4. Inspect Audit Logs
Review execution logs generated by the module:

Bash
cat ~/Portfolios/operation-heartless/door-to-darkness/logs/block_events.log
🛡️ Security Considerations
Production Deployment: In production environments, replace the Flask development server with a production WSGI server (e.g., gunicorn or uwsgi) and enforce TLS/HMAC signature validation on incoming webhooks.

Duplicate Protection: lock_door.py executes iptables -C checks prior to adding rules, preventing rule-table bloat and duplicate entries.
