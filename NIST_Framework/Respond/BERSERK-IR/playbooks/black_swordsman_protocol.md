# BERSERK-IR — Black Swordsman Incident Response Protocol

## Purpose

The Black Swordsman Protocol is the primary incident-response playbook
for the BERSERK-IR cybersecurity lab.

It provides a structured workflow for detecting, investigating,
classifying, containing, and documenting security incidents.

The Berserk-inspired terminology is the presentation layer.
The underlying workflow follows standard SOC and incident-response
principles.

---

## Phase 1 — The Brand

### Trigger

A security alert is generated by a monitored security control.

### Analyst Objective

Determine whether the alert represents:

- Benign activity
- Suspicious activity
- Confirmed malicious activity
- A false positive

### Evidence

Collect:

- Timestamp
- Source IP
- Destination IP
- Hostname
- Username
- Process
- Event type
- Alert/rule ID
- Related events

---

## Phase 2 — Awakening

### Objective

Validate the alert and establish initial scope.

### Questions

1. What triggered the alert?
2. Which host is affected?
3. Which account is involved?
4. Is the activity expected?
5. Are there related alerts?

---

## Phase 3 — Behelit Analysis

### Objective

Enrich the available evidence.

### Investigation Sources

- SIEM logs
- Endpoint telemetry
- Network telemetry
- Authentication logs
- IDS alerts
- Threat intelligence
- Historical events

### Output

Produce an initial hypothesis describing what may be occurring.

---

## Phase 4 — Apostle Hunt

### Objective

Determine whether the activity represents malicious behavior.

### Analyst Tasks

- Identify indicators of compromise
- Search for related events
- Identify affected assets
- Identify affected accounts
- Search for repeated activity
- Determine attack pattern

---

## Phase 5 — Causality

### Objective

Correlate individual events into an attack timeline.

### Questions

- What happened first?
- What happened next?
- Did the attacker move laterally?
- Was privilege escalation observed?
- Was persistence established?
- Are multiple hosts involved?

---

## Phase 6 — Threat Judgment

Assign a severity level.

### LOW

Limited suspicious activity with minimal evidence of compromise.

### MEDIUM

Credible malicious activity requiring investigation.

### HIGH

Confirmed malicious activity affecting a system or account.

### CRITICAL

Active compromise, significant privilege escalation,
lateral movement, data exposure, or widespread impact.

---

## Phase 7 — Dragonslayer Response

### Objective

Contain the threat while minimizing business impact.

Potential actions include:

- Block malicious network indicators
- Disable compromised accounts
- Isolate affected endpoints
- Terminate malicious processes
- Preserve evidence
- Escalate to Tier 2/Incident Response

No automated containment should occur without an appropriate
confidence threshold and response policy.

---

## Phase 8 — Aftermath

### Objective

Document the incident.

The incident report should contain:

- Executive summary
- Detection source
- Timeline
- Indicators of compromise
- Affected assets
- MITRE ATT&CK mapping
- Severity
- Actions taken
- Containment results
- Recommended remediation

---

## Phase 9 — Campfire

### Objective

Capture lessons learned.

Document:

- What worked?
- What failed?
- What generated the alert?
- Could the alert have been detected earlier?
- Was the playbook effective?
- Should detection rules be tuned?
- What defensive improvements are required?
